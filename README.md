# داشبورد تحلیل فروش QlikView

این Repository برای تبدیل مستقیم خروجی خام QlikView به داشبورد فروش طراحی شده است. فایل Excel نباید قبل از Upload به GitHub ویرایش شود.

## Workflow به‌روزرسانی

برای آپدیت معمولی فقط این کارها لازم است:

1. در QlikView همان ۲۱ ستون استاندارد را انتخاب کنید.
2. کل داده سال جاری از فروردین تا آخرین روز موجود را به فرمت **XLSX** دانلود کنید.
3. فایل را بدون هیچ تغییری با نام `raw/1405.xlsx` جایگزین کنید.
4. Commit کنید.
5. GitHub Actions به‌صورت خودکار Validation و Build را انجام می‌دهد.

ردیف‌های «سرجمع» QlikView به‌صورت خودکار حذف می‌شوند. لازم نیست Excel را باز کنید، فرمت اعداد را تغییر دهید یا ستون‌ها را Rename کنید.

## فایل‌های خام

```text
raw/
├── 1404.xlsx
└── 1405.xlsx
```

از ۱۴۰۶ به بعد کافی است `raw/1406.xlsx` نیز اضافه شود. اسکریپت سال را از خود فایل تشخیص می‌دهد.

## ستون‌های ضروری

- سطح سه کالاها
- سطح چهار کالاها
- برند
- نام کالا
- بارکد
- سال
- ماه
- روز
- مبلغ فروش خالص پس از برگشتی
- قیمت فروش به مشتری واحد کالا
- تعداد کالای فروش پس از برگشتی
- وزن فروش رفته پس از برگشتی

## ستون‌های تکمیلی استاندارد

در فایل ۱۴۰۵ این ستون‌ها نیز استفاده و اعتبارسنجی می‌شوند:

- مبلغ فروش خالص
- تعداد کارتن فروش رفته
- مبلغ تخفیفات فروش
- مجموع تعداد کالای فروش
- وزن فروش
- مبلغ خالص برگشتی
- تعداد کالاهای برگشتی
- وزن برگشتی
- تعداد فروشگاه

اگر یک فایل تاریخی مانند ۱۴۰۴ فاقد ستون‌های تکمیلی باشد، Build همچنان انجام می‌شود و مقدار آن شاخص‌ها برای آن سال خالی باقی می‌ماند.

## کنترل‌های خودکار داده

`scripts/build_data.py` در هر Build موارد زیر را کنترل می‌کند:

- وجود ستون‌های ضروری
- حذف ردیف‌های سرجمع
- معتبر بودن سال، ماه و روز
- یکتا بودن `سال + ماه + روز + بارکد`
- تطبیق `فروش خالص - برگشتی = فروش پس از برگشتی`
- تطبیق تعداد فروش و برگشتی
- تطبیق وزن فروش و برگشتی
- تشخیص آخرین روز موجود
- تولید Metadata تعداد SKU، برند و رکورد

در صورت خطای مهم، GitHub Action Fail می‌شود و داشبورد با داده معیوب منتشر نخواهد شد.

## ساختار پروژه

```text
.
├── raw/                    # فقط فایل خام QlikView
├── config/
│   └── source_config.json
├── scripts/
│   └── build_data.py
├── site/
│   ├── index.html
│   ├── styles.css
│   ├── app.js
│   └── data/               # خودکار ساخته می‌شود
├── .github/workflows/
│   ├── build.yml
│   └── deploy-pages.yml
└── requirements.txt
```

## ۱۴۰۴ و ۱۴۰۵

داده روزانه ۱۴۰۴ در QlikView برای Daily Trend قابل اتکا نیست، بنابراین در `config/source_config.json` سال ۱۴۰۴ به‌عنوان `daily_unreliable_years` مشخص شده است. تحلیل ماهانه، SKU، برند و YTD آن همچنان استفاده می‌شود.

داده روزانه ۱۴۰۵ معتبر است و در فایل جداگانه `site/data/daily/1405.json` ساخته می‌شود تا در نسخه‌های بعدی تحلیل Daily / Rolling Average / MTD روی آن اضافه شود.

## اجرای محلی برای توسعه

به دلیل محدودیت `file://`، فایل `index.html` را مستقیم Double-click نکنید. از یک وب‌سرور ساده استفاده کنید:

```bash
python -m http.server 8000 --directory site
```

سپس آدرس زیر را باز کنید:

```text
http://localhost:8000
```

در GitHub Pages این محدودیت وجود ندارد.

## GitHub Pages و محرمانگی

Workflow انتشار Pages عمداً به‌صورت دستی (`workflow_dispatch`) تنظیم شده است. قبل از انتشار باید مشخص شود چه کسانی مجاز به دیدن داده فروش هستند. فایل‌های `raw/*.xlsx` داخل Artifact سایت منتشر نمی‌شوند، اما داده پردازش‌شده موردنیاز نمودارها در سایت قابل دریافت است.
